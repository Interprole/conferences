# Поддержка каталога

Работать в этом репозитории. Владелец сам включает GitHub Pages; не менять настройки Pages. Сайт статический, файлы публикации лежат в корне. Коммиты — краткие, по существу изменений, без упоминаний ИИ и без приписок о соавторстве.

## Обновление данных

1. Сначала читать текущие файлы данных и их SHA; сохранять существующие `id`, пользовательские уточнения и историю. Не удалять старые конференции.
2. Проверять новые объявления LINGUIST List, каталог с пагинацией и все ещё актуальные конференции: дедлайны могут продлеваться и после закрытия первоначального срока. Учитывать и новые посты той же конференции, и изменения существующего поста. Сверять официальный сайт, когда доступен.
3. Gmail: искать именно рассылку Мослинг, например `(to:mosling@googlegroups.com OR subject:mosling)` с перекрытием последних 14 дней. Дочитывать страницы результатов, читать полные письма. Различать CFP, регистрацию слушателей, журнальные публикации и семинары. Первичная загрузка 2026 года неполная по вложениям; в следующих запусках дополнительно заполнять пробелы, начиная с будущих теоретических конференций.
4. Публиковать только название, место, сроки подачи и ответа, даты, сбор, тематику, языки исследования, рабочие языки, ограничения на выступающих, правила подачи, ссылки на публичный пост и сайт. Не включать исходные письма, приватные контакты, идентификаторы почтового ящика, пароли или закрытые ссылки на встречи. Ссылка Google Groups из футера может использоваться как источник; ссылка на личный Gmail не публикуется.
5. Неизвестные данные — `null`. Не удалось прочитать/распарсить источник — ясная запись в `notes` и журнале; не подменять это отсутствием ограничений. Сбор, регистрация слушателей и дедлайн тезисов — разные сведения. Subject Language(s) — не рабочий язык.
6. Для уточнённых сведений LINGUIST List использовать `data/overrides.json` по `id`, чтобы автоматический сбор не затёр исправления. При продлении сохранять старую дату и добавить `history` с `field: deadline`, `old`, `new`, `type: extended`, `observed_at` и ссылкой `source`. При неизвестной старой дате — `old: null`; продление допускается только при прямом подтверждении источника.
7. Отбор: не включать специализированные переводоведение, культурологию, NLP, нейролингвистику. `classification: theory` — синтаксис, семантика, морфология, фонетика, фонология, просодия, грамматическая типология и формальная теория языка; `mixed` — смешанная тематика. Тематические секции не объединять с основной конференцией, если отличаются условия подачи. Повторы разных источников объединять только по подтверждённой идентичности; `merge_key` можно установить одинаковым.
8. Обновлять `checked_at` только для реально проверенной записи. `verification: reviewed` — объявление прочитано и поля проверены; `partial` — извлечено не всё. При конфликте дат использовать `date_conflict` и не рассчитывать статус проведения по спорной дате.
9. Обновлять независимые журналы источников. `last_success_at` — реальная успешная проверка, `attempted_at` — попытка. `complete: false` при пропусках. Не отмечать весь источник обновлённым только из-за пересчёта дней.
10. При сбоях сохранять старые данные, явно сообщать о проблеме. Не пытаться обходить ограничения источника. Проверять SHA перед записью; при конфликте перечитать изменившийся файл. Разные источники обновляют разные файлы журнала.

## Проверка

После изменений кода: `npm run check`. После обновления данных: JSON должен разбираться, даты — ISO `YYYY-MM-DD`, URL — http/https, стабильные ID уникальны, история не потеряна. Не включать сырые почтовые выгрузки, `.preview/`, `.openai/`, секреты или временные файлы в коммит.

## Критерий тематического выделения

Для выделения цветом использовать широкий критерий владельца: грамматика конкретного языка или языков вообще, включая описательную и корпусную грамматику, типологию, отрицание, падеж, согласование, синтаксис, семантику, морфологию, фонетику, фонологию и просодию. Корпусный метод или наличие смежных секций не отменяют отметку theory. Общелингвистические конференции с рубрикой General Linguistics выделять как theory, если нет явной преимущественно прикладной или иной смежной специализации; General Linguistics сама по себе — широкая рубрика, а не неизвестное значение. Специализированные исключённые направления по-прежнему не показывать.

## Ручной анализ и представление

По последнему указанию владельца автоматический парсинг по расписанию отключён. Ежедневная задача продолжает проверку в 09:00 МСК, но читает и анализирует объявления самостоятельно, не запуская scripts/refresh.py. Не возвращать cron сборщика без указания владельца. Не использовать регулярные выражения и рубрики вместо содержательного решения о тематике.

Поддерживать data/editorial.json: все места подписывать по-русски; содержательное резюме тематики и исследуемые языки показывать под названием. Не путать исследуемые и рабочие языки. Неизвестные языки не превращать в «любые». Связи секций записывать явными списками id одного выпуска конференции, с основанием. Группировка визуальная: каждая секция сохраняет собственные сроки и условия, не объединять её данные с основной конференцией. Обновлять локализацию для каждого нового места.

Сайт показывает только таблицу. Системная тема включена по умолчанию, ручной выбор светлой / тёмной темы сохраняется локально.
